## 3. 비기능 요구사항의 정량 목표 제안

| SRS ID | 측정 항목 | 초기 목표 제안 | 측정 조건 | 확정 전 확인 사항 |
| --- | --- | --- | --- | --- |
| NRF_01 | 행정 담당자의 센터 접수 물품 1건 평균 등록 소요 시간 | **60초 이하** | 필요한 정보를 미리 제공한 센터 접수 가상 물품 20건을 같은 담당자가 기존 방식과 서비스에서 각각 등록한다. 서비스 연습 5건 후 입력 시작부터 저장 완료 안내까지 측정한다. | 필수 입력 항목, 현재 등록 시간, 업무 난이도. 60초 이하라는 사실만으로 기존 업무보다 개선되었다고 판단하지 않는다. |
| NRF_02 | 조회 실행부터 보관 여부·위치·문의 정보 표시 완료까지의 시간 | **p95 2초 이하** | 가상 물품 1,000건, 동시 조회 사용자 20명, 준비 실행 1분 후 5분 이상·총 200회 이상 측정. 클라이언트·서버·네트워크 조건과 실패한 조회를 별도로 기록한다. | 성능 요구 채택 여부, 실제 예상 부하, 측정 환경. 성공 응답의 p95만으로 전체 기능의 합격을 판단하지 않는다. |

위 수치는 초기 설계·검증을 시작하기 위한 제안이며 고객 확정값이나 보편적 표준값이 아니다. 최종 기준은 SRS에서 관리하고 변경 시 이 표에도 반영한다. p95는 측정값의 95%가 해당 시간 이하임을 뜻한다.

## 4. 추적 결과 및 변경 사항

| 구분 | 결과 |
| --- | --- |
| 고객 요구 추적 | NEEDS_1~NEEDS_7의 7개 항목 모두 연결했다. NEEDS_5는 범위 미정 상태를 유지했다. |
| 개발 범위 추적 | SC1~SC8의 8개 항목 모두 연결했다. SC5·SC7은 제외 정책으로, SC8은 비공개 제약과 정책으로 연결했다. |
| 공통 제약 추적 | C_1의 가상 데이터 사용·실제 개인정보 제외와 학교 인증 연동 제외를 각각 연결했다. |
| SRS 역추적 | 기능 7개, 비기능 5개, 정책 8개 등 총 20개 항목의 근거를 기재했다. 분석 제안에는 제안임을 명시했다. |
| 일반 품질 속성 제외 | 기존의 일반적인 사용 편의성, 데이터 정확성·일관성은 독립 비기능 항목에서 제외했다. 정보·상태의 일치 여부는 기능 검증 기준에서 확인한다. |
| 정량 목표 보완 | 등록 시간과 조회 응답 시간에 제안 목표와 측정 조건을 기재했다. 고객이 이미 합의한 수치로 간주하지 않는다. |
| 구체적 제약 유지 | 개인 번호 비공개·공개 범위 제한, 가상 데이터 사용, 학교 인증 연동 제외는 원문에 명시된 구체적 제약이므로 유지했다. |
| ID 정리 | 비기능 요구사항을 NRF_01~NRF_05로 연속 정리하고 SRS 내 참조를 갱신했다. 이전 초안의 NRF ID 대신 현재 SRS의 ID를 기준으로 추적한다. |
| 검증 상태 | 이 문서는 요구사항 간 연결을 검토한 결과다. 구현 및 인수 시험 결과는 아직 포함하지 않는다. |
